# Demo manifests

Generated by `ProofEngine.build_demo_manifest(...)` — real RFC 8785
canonicalization, a real SHA-256 digest, and a real secp256k1 signature, but
stamped `"mode": "DEMO"` / `"verification_status": "DEMO_ONLY"` at the
manifest root so `public/verify.html` (and any other correctly-written
verifier) refuses to ever report them as `VERIFIED`, however cleanly their
cryptography checks out.

- `demo-valid.json` — unmodified since signing. Open it in `verify.html` and
  every crypto check passes ([PASS] digest match, [PASS] signature valid),
  but the final result is still `◆ DEMO ONLY`, never a verified state.
- `demo-tampered.json` — `payload.audit.query` was changed after signing,
  leaving the original `digest`/`signature` fields untouched. `verify.html`
  correctly reports `[FAIL] DIGEST MISMATCH` — proving tamper-detection
  actually works, not just that the demo flag works.

Regenerate both with:

```python
from ecdsa import SigningKey, SECP256k1
from backend.proof_engine import ProofEngine

engine = ProofEngine(private_key_pem=SigningKey.generate(curve=SECP256k1).to_pem())
demo = engine.build_demo_manifest("AI_VISIBILITY_AUDIT", {
    "audit": {
        "query": "...", "provider": "...", "model": "...",
        "timestamp": "2026-01-01T00:00:00Z", "response_hash": "00" * 32,
    }
})
```

Both files were confirmed against a real headless run of `public/verify.html`
(not just asserted in Python) — see `../README.md`'s Status section.
